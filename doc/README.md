# SVG 命令行编辑器：设计与实现记录

本项目对应 `phase_cli_1.md` 中的 Lab1 Phase 1，使用 TypeScript 严格模式和面向对象设计，实现六种内置图形及全部 19 条课程命令。box 和插件加载器留到后续阶段。

## 1. 架构方案

### 1.1 模块划分与职责

| 模块                             | 主要对象                                                         | 职责                                                |
| -------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| `src/domain/`                    | SvgDocument、Shape、GeometryShape、六类图形                      | 管理几何、属性、id 和有序树，提供多态编辑与深拷贝   |
| `src/application/`               | SvgEditor、CommandHistory、ShapeFactory                          | 组织文档操作、编辑事务、历史屏障和图形创建          |
| `src/application/commands/`      | EditCommand、十个具体编辑命令                                    | 将编辑请求封装为对象，保存执行和撤销/重做所需的状态 |
| `src/application/ports/`         | FileStore、SvgCodec 接口                                         | 约定文件读写和格式转换的接口                        |
| `src/cli/`                       | Tokenizer、CommandArguments、CommandRouter、ShapePresenter、Repl | 解析命令、显示文本并处理逐行交互                    |
| `src/infrastructure/`            | LocalFileStore、XmlSvgCodec                                      | 实现文件 IO 和 XML/SVG 转换                         |
| `src/bootstrap/`                 | main.ts                                                          | 创建对象、注入依赖，选择交互、脚本或管道模式        |
| `test/`、`examples/`、`scripts/` | 测试、示例、架构检查脚本                                         | 复现操作场景，检查功能和依赖规则                    |

图形的字段由类封装，外部通过方法修改几何、样式和父子关系。`geometry()`、`attributes()` 返回新的只读对象，`children()` 返回数组副本。修改返回的属性对象或数组，不会直接改变原对象的字段或子节点顺序；数组中的节点仍是原对象引用，节点本身通过方法编辑。id 区分大小写；内部使用的画布根节点不占用用户 id。

查找图形时，SvgDocument 直接遍历树，时间复杂度为 O(n)。初稿考虑过 id 索引，但当前没有性能数据说明需要同时维护树和索引，因此先采用容易保持一致的实现。以后确有查找瓶颈，再在 SvgDocument 内部增加索引。

### 1.3 设计模式的选择与实现

#### Command：让编辑请求成为对象

CreateCommand、DeleteCommand、MoveCommand、ScaleCommand、SetCommand、GroupCommand、UngroupCommand、AddToCommand、FrontCommand 和 BackCommand 都继承 EditCommand。CLI 解析好参数后创建命令，命令只处理编辑，不读取终端或写文件。

CommandHistory 在命令成功后记录历史。undo 后再执行新编辑会清空 redo，tree、show、help 等显示命令则不进入历史。

#### 快照：恢复编辑前后的完整状态

EditCommand 先克隆当前文档，在副本上执行操作并校验结果，成功后由 SvgEditor 替换当前文档。命令保留编辑前后的文档，后续操作继续使用新的副本，所以历史状态不会被后续编辑修改。undo/redo 直接恢复快照，不需要重新执行命令或分配 id，采用的是 Memento 的思路。

选择快照，主要是因为分组、解组和删除都涉及父链接、子树与兄弟顺序，手写逆操作很容易漏掉其中一项。这种做法每次编辑需要 O(n) 复制，h 条历史占用 O(hn) 空间。早期实现自行加过 100 步截断，复查时发现课程没有这个限制，后来将其移除。大文档场景仍需考虑增量存储、不可变树共享或可配置的资源限制。

#### Composite：对容器和叶子使用同一套操作

Shape 定义 move、scale、setAttribute、clone 等方法。叶子类修改自身几何，Group 将移动和缩放递归交给子节点；删除 Group 时删除整棵子树。命令只调用这些方法，不需要按图形标签选择几何算法。

#### Factory：集中处理图形创建

ShapeFactory 统一处理“类型名 → 构造策略”，CLI 创建和 SVG 导入共用这个入口。参数 schema 与构造策略集中登记，属性是否合法仍由图形对象检查。

按课程要求，当前保留两处名称分派，并将其列为后续重构点：

1. CommandRouter 按命令名调用用例，后续可提取命令提供者注册接口。
2. ShapeFactory 按类型名构造内置图形，后续可改为 ShapeProvider 注册机制。

这两处以外的图形操作使用多态。第一阶段尚未实现插件系统。

### 1.4 依赖方向规则

| 来源           | 可依赖模块                          | 理由                                       |
| -------------- | ----------------------------------- | ------------------------------------------ |
| domain         | domain                              | 几何和树结构应独立于运行环境               |

| cli            | cli、application、domain            | 调用应用用例，使用领域值校验和只读数据展示 |

## 2. 行为约定与阶段边界

课程没有完全规定的细节在这里说明，便于按同样的规则复验。若后续课程解释有调整，应据此修改实现和测试。

### 2.1 几何、分组与绘制顺序

scale 将位置和尺寸一起乘以正系数，不修改 stroke-width、文字内容和字号，也不写入 transform。对 g 设置 fill/stroke 时使用 SVG 继承，子节点已有的显式样式继续生效。

group 至少接收一个目标。目标重复，或同时选中容器及其子孙时，整条命令失败。新组内的顺序按操作前文档的深度优先绘制顺序确定，与命令参数顺序无关。新组放在目标的最低共同祖先中，占据首个目标所在直接分支的位置；原容器即使变空也会保留。

跨层分组后，节点的继承样式可能随新父级改变，当前不会计算并固定全部 CSS 样式。undo 可以恢复原来的层级和属性。ungroup 按课程要求拒绝顶层容器；嵌套容器解散后，子节点按顺序占据原容器的位置。未显式覆盖的常见样式会补给子节点，保留原来的继承结果，id、data-kind 等元数据则不会随之复制。

front 将节点移到兄弟列表末尾，back 移到开头，对应 SVG 中后绘制的元素覆盖先绘制的元素。addto 将目标追加为容器的最后一个子节点，并检查是否会形成环。

### 2.2 历史与失败处理

每条成功编辑都是一个历史单元，包括位移为零的 move。显示命令和失败命令不入栈。成功的 init、read、save 和 canvas 尺寸修改会清空历史、设置屏障，此时 undo/redo 返回 `error: undo not allowed after io command`。下一条成功编辑会解除屏障并建立新历史；失败编辑不会解除屏障，canvas 查询也不会设置屏障。

编辑先在副本中执行。即使递归缩放到后半段才发生溢出，当前文档也不会留下部分修改。提交编辑前会检查整棵树的 id 唯一性、父链接、无环和 128 层深度上限。CLI 与导入器共用这一上限，避免出现能创建、保存后却无法读回的结构。

read 通过完整 XML、id、属性和子树检查后才替换文档，并输出自动补 id 的警告。save 在目标目录写入唯一临时文件，再重命名替换目标。保存失败时清理临时文件，当前文档、历史和路径都保持原状。

无参数 save 优先使用最近一次 read 的路径，显式另存到其他文件不会改变这个默认目标。init 新建的文档可由首次成功保存建立默认路径，再次 init 会清除路径。这种文件替换方式不保证断电后的持久性，也没有处理多个进程同时保存同一文件的冲突。

### 2.3 SVG 导入范围

导入器支持六种内置元素、浮点坐标、px 画布尺寸、默认值为 0 的几何属性、文本/CDATA，以及 fill、stroke、stroke-width。font-size、text-anchor、data-kind 等附加属性可以保存后读回。画布尺寸未指定时使用 800×600。

补 id 前先收集文件中所有显式 id，再按“标签名+序号”分配，避免与文件后部的名称冲突。重复 id、非法维度和无效 XML 会使导入失败。根 svg 不参与图形 id 寻址。

元素上的 translate(x[,y])、scale(s) 和 scale(s,s) 可以串联、嵌套，其中缩放必须为正且等比。变换列表按 SVG 顺序后乘，嵌套使用 parent∘local。例如 translate(10,20) scale(2) 会把 (3,4) 变为 (16,28)。导入器把每个叶子的累计变换应用到几何，保留 g 层级，导出时不再保留 transform。此后的 show、set、move 使用画布坐标；CLI scale 仍按课程要求只缩放几何。

SvgImportContext 记录原始继承长度和累计变换，防止对子孙重复缩放。字号和 stroke-width 在有自身值或局部缩放变化时固定为数值，未覆盖的子节点继续继承。嵌套逆缩放相消时，也会重置父级已经放大的值。线宽初值为 1；没有显式字号时，项目采用常见桌面环境的 16px 约定，SVG 规范并未把 medium 固定为这个值。实现参考了 [SVG 1.1 坐标变换](https://www.w3.org/TR/SVG11/coords.html#TransformAttribute) 和[样式继承](https://www.w3.org/TR/SVG11/styling.html#Inheritance)。

当前不支持旋转、不等比或非正缩放、一般 matrix、CSS、path、tspan、非 SVG 命名空间、非 xml 的命名空间附加属性、百分比画布尺寸、根级附加样式，以及使用不同坐标系的 viewBox。若文件带有 viewBox，它必须为 `0 0 width height`。缩放下尚未处理的虚线、字间距、文字偏移、圆角等长度敏感附加属性，以及相对字号单位，也会被拒绝，避免读入后静默改变外观。DTD、实体声明、样式表处理指令和事件属性同样不接受。

普通附加属性可以往返保存，但复杂透明度和引用等高级语义在重组或修改几何后可能改变，不在本阶段的编辑保证内。需求开头的嵌套 translate/scale 示例已加入回归测试和离线渲染检查。

SvgString 在模型入口检查 XML 1.0 字符合法性，包括孤立代理项，非法字符串不会进入历史或文件。编码时将文本中的回车写为字符引用，避免读回时被 XML 换行规范改成 LF。`data-kind="box"` 则按普通 g 读回并保留标记；create box 仍报 unknown shape type。

### 2.4 命令行交互

- `#` 只在行首（忽略前导空白）表示整行注释，颜色值中的 `#` 会保留。
- 双引号支持空字符串、空格、转义引号和反斜杠。其他反斜杠按字面保留，便于输入 Windows 路径。引号内的文字 `"in"` 不会被当成 create 尾缀。
- 终端模式显示欢迎语和 `svg>`，管道和脚本模式不显示提示符。
- 脚本出错后继续执行剩余行；出现错误时最终退出码为 1，全部成功为 0。交互模式遇到错误后继续等待输入。
- 错误字符串遵守课程约定。成功和撤销反馈使用结果摘要，措辞不逐字复刻课程示例。

## 3. 过程记录

开发中使用 Codex 协助编写代码、文档和测试，过程中遇到的问题和调整记录如下。提交前，提交者还需亲自运行项目、阅读代码，并补充自己的判断。

### 3.1 从需求到第一版实现

最初目录里只有需求文件，没有代码和 Git 仓库。梳理时先确认 box 属于后续阶段，再提交架构初稿和工程骨架，按模块推进实现。

模型设计有过两次调整。第一处是查找方式：初稿提到 id 索引，但没有性能证据支持维护两份结构，因此改用树遍历。第二处是撤销方式：分组和删除若各自实现逆操作，容易漏掉父链接和顺序，后来统一采用副本执行和前后快照。

第一轮构建也暴露了具体问题。TypeScript 7 没有加载所需的 Node 类型，于是在配置中显式加入 `types: ["node"]`；XML 节点的 localName 类型可能为空，补上 tagName 后备后才通过严格编译。本机 npm 系统缓存不可写的问题，则通过项目 `.npmrc` 使用本地缓存解决，没有修改全局权限。

### 3.2 测试推动的修正

| 发现的问题                                               | 确认和修改方式                                                                         |

### 3.3 再次对照实验要求

使用者提出“再根据试验文档检查还有什么没有完成”后，复查从命令是否存在扩展到了行为细节。其中，100 步历史截断和无参数 save 的默认路径都需要修正。

100 步截断是实现时自行加入的限制，课程没有要求。移除后，用 106 条连续编辑检查完整撤销和重做。save 的问题更隐蔽：`read A.svg → save B.svg → 编辑 → save` 原先会写入 B，而课程要求无参数时保存到读入路径。修正后，另存不会改变最近 read 的默认目标，并增加读入另一文件后目标随之更新的测试。

字符串和样式检查还补出了几处问题。非法控制字符会使输出 XML 无法打开，因此由 SvgString 统一拒绝；文本中的 CR 要保留为字符引用；外部样式表不能被静默忽略。解组时，显式 `fill=inherit` 原先会改为继承新父级，现在会先沿原继承链求值再保存，并用回归测试检查结果。

2026-10-21 的收尾工作加入了常见 SVG 变换归一化。独立复查比较了 48 组支持范围内的嵌套组合，没有发现需要修正的语义错误，部分栅格边缘有轻微浮点或抗锯齿差异。课程变换示例在同一离线渲染器下比较，原图与导入保存后的图像像素差为 0；流程图、历史示例和变换示例的 PNG 也经过查看，确认中文、颜色、布局和连线可见。

### 3.4 验证环境与远程交付

浏览器本地预览请求曾被权限策略拒绝，随后停止检查并关闭临时服务器。后续使用本地 resvg-js 渲染 PNG，完成图像比较和查看；浏览器原生显示仍未验证。文件和子进程测试也曾因受限临时目录的权限失败，在正常本机文件权限环境下复验通过。离线脚本一度反复读取原生 pixels getter，造成重复复制，后来改为缓存两个像素缓冲区。

使用者授权新建仓库后，项目通过已有 GitHub 凭据创建私有仓库并分步推送，凭据没有写入项目。2026-10-27，按使用者要求将仓库改为公开，并验证了匿名访问。GitHub 此前拒绝了工作流推送，因为当前 OAuth 缺少 workflow 权限。配置因此保留为 `ci/github-actions.yml` 模板，尚未启用。`final` 标记最终交付，历次交付另留归档标签。

## 4. 一致性自查

### 4.1 实际目录与方案是否一致

实际目录与修订后的方案一致。运行时导出的类一类一文件，文件名与类名匹配；main.ts 负责对象装配。相对初稿的调整包括树遍历查找、允许 CLI 使用受限领域接口、采用快照历史，以及明确 SVG 导入子集，均已在前文记录。

### 4.2 依赖方向是否符合规则

静态检查没有发现违反最终依赖规则的导入。源码抽查的结果如下：

- Rect 依赖领域中的 GeometryShape，没有 XML 或命令行依赖。
- SvgEditor 依赖 FileStore/SvgCodec 端口类型，没有导入具体适配器。
- MoveCommand 调用 shape.move()，不按图形标签分支。
- CommandRouter 创建命令，通过 editor.edit() 修改文档。
- XmlSvgCodec 实现 SvgCodec，DOM 类型没有进入领域层。
- main.ts 装配工厂、端口实现、应用和 CLI。

这些检查说明当前实现与方案相符。后续新增代码仍需检查实际调用，静态导入规则无法覆盖所有运行时行为。

## 5. 质量保证手段

### 5.1 如何复验

在仓库根目录执行：

```sh
npm ci
npm run check
npm run test:coverage
npm run cli -- --script examples/flowchart.commands
npm run cli -- --script examples/history.commands
npm run cli -- --script examples/transforms.commands
```
